Heart Walk Deck: Architecture & Usage GuideThis document serves as the "Instruction Manual" for both human operators and AI agents generating content for the Heart Walk Deck application. It details the app's capabilities, hidden positioning logic, and the strict JSON schema required for ingestion.1. Core ConceptThe Heart Walk Deck is a client-side, browser-based slide editor. It bridges the gap between simple HTML design and professional PowerPoint (.pptx) export. It relies on localStorage for saving progress and uses PptxGenJS for generation.2. Key Features & Hidden MechanicsThe Nudge System (Positioning)The app uses a 3-layer positioning system. This is often missed by new users.Global Mode: Moves elements on every slide simultaneously (e.g., shift everything down 10px).Template Mode: Moves elements only on slides of the same type (e.g., move titles on all "Cover" slides).Local Mode: Moves elements only on the current active slide.Toggle this by clicking the "Mode" text in Settings.Context ActionsUsers can interact with elements using specific mouse/keyboard combos:Ctrl + Click: Selects a text block (Title or Body).Ctrl + Arrow Keys: Nudges the selected block(s).Right Click (on Cover/Section): Opens a color menu to change the decorative background shape.Note: Markdown Parsing > The app parses text input for Markdown.Use **bold**, *italic*, ### Header, and * Bullet points.When exporting to PPTX, ### Headers are converted to Bold text with extra spacing.3. JSON Schema DefinitionTo ingest data into the app, generate a JSON object with two root keys: config and slides.The Config Object{
  "config": {
    "font-title": "'Source Sans 3', sans-serif",
    "size-title": "32pt",
    "color-title": "#16bfec",
    "showShapes": true,
    "globalX": 0,
    "globalY": 0,
    // Template Offsets (Auto-generated by app, but can be injected)
    "typeOffsets": {
        "cover": { "x": 0, "y": 0 },
        "section": { "x": 0, "y": 0 },
        "standard": { "x": 0, "y": 0 }
    }
  }
}
The Slides Array{
  "slides": [
    {
      "type": "cover",          // Options: "cover", "section", "standard"
      "title": "Project Alpha",
      "subtitle": "Q1 Report",  // Only used for "cover"
      "shapeColor": "var(--c-emotional)", // Optional: overrides default shape color
      "x": 0, "y": 0,           // Local slide offset
      "titleX": 0, "titleY": 0, // Local title offset
      "bodyX": 0, "bodyY": 0    // Local body offset
    },
    {
      "type": "standard",
      "title": "Key Metrics",
      "content": "### Growth\n* Revenue up 20%\n* Users up 15%" // Markdown supported
    }
  ]
}
4. Robust Ingestion StrategyThe app now includes a Sanitizer Engine to handle imperfect JSON input from external AI agents.Warning: Philosophy > "Accept everything, break nothing."Missing Fields: If a required field (like type) is missing, the app defaults to standard. If config is missing, it loads the default brand palette.Unexpected Fields: If the input contains extra fields (e.g., "ai_notes": "check this"), the app preserves them in the data structure but ignores them for rendering. This ensures data isn't lost during an Export -> Modify -> Import cycle.Reporting: Instead of throwing errors, the app displays a "toast" notification listing what was auto-corrected (e.g., "Slide 3 missing type, defaulted to standard").
